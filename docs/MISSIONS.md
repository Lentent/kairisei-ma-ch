# 任务系统

服务端复用客户端现有的任务列表、完成提示和领奖接口。无需清档，旧账号的等级、卡牌图鉴和累计签到会计入成长任务。

客户端分类按 `MISSION_TAB_TYPE` 映射：每日任务使用 `tab_type=2`（DAILY），成长任务放在成就页，使用 `tab_type=0`（PERMANENT）；`1` 是限时任务。旧存档中的任务在下次任务刷新时同步修正分类，进度、已领取状态及已发礼物保留。

首次升级时沿用旧配置中的9项任务及其已修改的标题、目标、奖励和启用状态。原“公告与奖励”页面的固定任务表已移除，改为独立的“任务管理”页签。迁移后任务配置独立存入数据库；编辑公告、签到或看板不会覆盖任务配置。以下是包内初始任务，可以继续编辑、复制或移除，并非固定数量：

| 类型 | 条件 | 水晶奖励 |
| --- | --- | --- |
| 每日 | 当天登录 | 1 |
| 每日 | 完成一次探索 | 2 |
| 成长 | 达到10、30、50级 | 分别5、10、15 |
| 成长 | 图鉴收集20、50种卡牌 | 分别5、10 |
| 成长 | 累计签到7、30天 | 分别5、15 |

每日任务在北京时间00:00重置；前一天未领取的任务奖励不保留。已领取至礼物箱的奖励不受重置影响。探索按成功结算时间归属日期，重复提交结算不会增加进度。

任务领奖后，奖励发送到礼物箱，每种奖励一封礼物；领取礼物后才进入背包或增加货币。支持批量领取；只要选择中存在未完成任务、重复任务或已领取任务，整批拒绝。成长任务每个账号只能领取一次。任务进度、每日日期和已领取状态随账号存档保存。

后台进入“任务管理”，左侧可按名称、ID、分类及启用状态筛选任务，右侧编辑当前任务。支持新增、复制、移除任务，以及修改标题、说明、每日／成就分类、完成条件、目标、奖励和启用状态。全部修改在点击“保存任务配置”后生效；切换后台页签保留未保存草稿，刷新或关闭页面有提示。任务最多200项，允许移除全部任务并保存空列表。

目前支持四种完成条件：登录、探索结算、玩家等级、卡牌图鉴种数。同一条件可以添加多项任务；登录和探索支持每日或成就分类，等级和图鉴只支持成就分类。每日登录目标固定为1。成就登录使用已有累计签到天数；成就探索统计该任务启用期间的有效探索结算，不补计旧版未记录的历史探索。暂未实现指定Boss通关、抽卡等新计数条件，修改标题或说明不会改变完成条件。

每项任务配置1–4种奖励，使用后台现有奖励目录选择货币、卡牌、素材卡、道具、召唤石、传承卡、皮肤、表情或称号。卡牌、召唤石、传承卡数量为1–100；皮肤、表情、称号固定为1；其他奖励为1–10000000。卡牌等级、名声、忠诚度不得超过该卡牌的目录上限，技能等级由服务端统一设置。任务标题最多60字，说明最多200字，目标为1–10000000。

修改标题、说明、目标或奖励保留任务ID、进度和领取记录。未领取的任务采用新目标和新奖励；提高目标后可能需要继续完成任务。已经领取的任务不会重新开放，礼物箱中已发放的奖励也不改变。停用后隐藏并禁止领取，重新启用不会重置领取记录；探索只统计启用期间的有效结算，达到目标后停止累计。

新增及复制任务在保存时自动分配新ID；改变完成条件或每日／成就分类也创建新ID，并移除原任务。原任务的领取记录不转移到新任务，因此符合新条件的玩家可以领取新任务奖励。移除任务后旧ID永久退役，不用于后续任务；已发礼物不撤回。删除所有任务后不会自动恢复默认任务。包内默认任务定义位于 `server/internal/game/missions.go` 的 `localMissions`。

后台独立接口为 `GET /api/missions` 与 `PUT /api/missions`，保存携带 `expected_revision`，避免多人编辑覆盖。新任务提交 `id:0`，由后台分配ID；同一配置内已有ID不可重复。审计记录使用 `mission-policy` 操作类型。

服务端测试覆盖进度计算、领奖原子性、重复领取、跨天重置、状态序列化和探索结算。客户端任务页的分组、倒计时和交互仍需使用配套APK进行实机验收。
