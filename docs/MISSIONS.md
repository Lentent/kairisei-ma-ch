# 任务系统

服务端复用客户端现有的任务列表、完成提示和领奖接口。无需清档，旧账号的等级、卡牌图鉴和累计签到会计入成长任务。

| 类型 | 条件 | 水晶奖励 |
| --- | --- | --- |
| 每日 | 当天登录 | 1 |
| 每日 | 完成一次探索 | 2 |
| 成长 | 达到10、30、50级 | 分别5、10、15 |
| 成长 | 图鉴收集20、50种卡牌 | 分别5、10 |
| 成长 | 累计签到7、30天 | 分别5、15 |

每日任务在北京时间00:00重置；前一天未领取的任务奖励不保留。已领取至礼物箱的奖励不受重置影响。探索按成功结算时间归属日期，重复提交结算不会增加进度。

任务领奖后，奖励发送到礼物箱，领取邮件后才增加水晶。支持批量领取；只要选择中存在未完成任务、重复任务或已领取任务，整批拒绝。成长任务每个账号只能领取一次。任务进度、每日日期和已领取状态随账号存档保存。

后台进入“公告与奖励 → 任务配置”，可修改现有9项任务的标题、目标、水晶奖励和启用状态，然后点击页面顶部“保存配置”。每日登录目标固定为1；任务类型和ID保持不变。配置写入数据库，重启保留，玩家下一次请求时生效。

未领取的任务采用新目标和新奖励；提高目标后可能需要继续完成任务。已经领取的任务不会重新开放，礼物箱中已发放的奖励也不改变。停用后隐藏并禁止领取，重新启用不会重置领取记录；每日探索只统计启用期间的有效结算，达到目标后停止累计。

包内默认任务定义位于 `server/internal/game/missions.go` 的 `localMissions`。旧版运营配置自动补入默认任务。后台暂不支持新增任务类型或删除任务；可用启用开关控制开放。任务ID是已领取记录的标识，不应复用于不同的任务。

服务端测试覆盖进度计算、领奖原子性、重复领取、跨天重置、状态序列化和探索结算。客户端任务页的分组、倒计时和交互仍需使用配套APK进行实机验收。
