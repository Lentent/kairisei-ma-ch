# 1.3.1 多公告修改版

基于上游 1.3.1（33a5733），移植原 1.3.0 本地多公告、公告去目录及主页新公告提示修改。

## 公告操作

进入后台「公告与奖励」：

1. 点击「新增公告」，填写标题和正文。
2. 勾选「上架这条公告」决定是否公开；取消勾选即可下架并保留草稿。
3. 勾选「置顶」使该公告在游戏页面优先显示。
4. 使用「上移」「下移」调整顺序。置顶公告之间、普通公告之间分别保留该顺序。
5. 点击页面顶部「保存配置」发布。删除、上下架和排序也要保存后才生效。
6. 点击「查看已发布公告」检查结果。

游戏公告页直接展开全部已上架公告的正文；不显示顶部目录或返回目录链接。

最多50条，每条标题1–80字、正文最多8000字。正文为纯文字，保留换行。已上架且总开关开启时，正文不能为空。
总开关关闭只隐藏公告，不删除已保存内容。

## 现有数据

旧版本保存的单条公告自动作为第一条显示，无需手工修改数据库。读取旧配置不写数据库；首次保存多公告后使用新结构。删除全部公告后保持空列表，不会恢复旧标题和正文。

公告与签到、新手毕业邮件、剧情奖励和看板设置仍沿用同一保存入口及版本冲突检查。仅编辑公告不会重置这些配置或玩家领取进度。

多公告数据不兼容上游单公告后台的编辑方式。若要回退程序，先备份当前数据库；上游版本只能读取旧单条字段，无法管理新增列表。

## 编译与替换

安装 Go 1.25 或更高版本。在源码根目录运行：

```powershell
.\tools\powershell\Build-Server.ps1
```

脚本执行测试、静态检查，再将三个平台的服务端输出到 `_local/bin/`。

部署目标必须先具有完整且配套的 1.3.1 服务端资源和 APK。正常停服并备份整个 `_local/data/` 及原服务端程序，然后只替换自己平台的程序：

| 系统 | 程序 |
| --- | --- |
| Windows x64 | kairi-server.exe |
| Linux x64 | kairi-server-linux-amd64 |
| Linux ARM64 | kairi-server-linux-arm64 |

Linux 替换后用 `chmod +x` 恢复对应程序的执行权限，再通过原启动脚本启动。
保留原来的 `resource-set/`、`deployment.json`、`cdn.json`、启动脚本和存档。此公告修改本身无需重打 APK 或上传游戏资源。

## 修改位置

- `server/internal/admin/admin_notices.go`：多公告定义、旧数据兼容、校验与置顶排序。
- `server/internal/admin/web/notices.html`：游戏公告页面，正文直接展开。
- `server/internal/admin/admin_player_policy.go`：接入公告校验，并提高配置请求大小上限。
- `server/internal/admin/web/admin_player_policy.js`、`admin_ui.html`、`admin_ui.css`：后台编辑与展示。
- `server/internal/admin/admin_notices_test.go`：数据升级、保存重启、隐藏、置顶、删除全部、文本转义及容量限制测试。

## 验证范围

此前 1.3.0 修改曾做过浏览器公告操作验证。此次迁移到 1.3.1 的检查与部署范围见 [本地修改说明](LOCAL-CHANGES.md)；此前的 1.3.0 二进制包不能作为本仓库新版程序使用。

## 新公告主页自动提示（2026-09-23）

行为：
- 已发布公告内容变化后，下次进入游戏主页自动打开公告页面。
- 公告页面被请求后记录已读，同一角色不再重复；重启保留，各角色独立。
- 第一次安装此功能时，当前有效公告会提示一次。
- 修改未上架草稿、调整置顶和排序、修改其他奖励配置，不触发新提示。
- 关闭公告总开关或没有已上架公告时不弹出；重新打开总开关后提示一次。
- 新手训练期间暂不弹出，完成后进入主页再提示。
- 玩家停留在主页时不会主动推送；需要再次进入主页或重新登录。
- 直接打开后台预览不影响角色已读状态。


技术说明：公告独立 publication_revision 由服务端保存时计算，客户端不能指定。HomeShow 的 update_info_url 返回相对于登录 web_url 的地址；原生主页在签到/新手相关流程后调用 Home.CheckNotice。/disabled/web/auto 用仅授予指定角色和公告版本已读权限的 HMAC token 标记已读；页面请求日志不记录 token。复用角色 popup_read_ids 保存已读，无需数据库 schema 升级。旧页面请求不会标记较新版本已读。
