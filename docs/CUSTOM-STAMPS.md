# 自制表情

后台侧栏“扭蛋与商店 → 自制表情”提供三种类型：纯文字、图片、图片加声音。页面随服务端程序发布，使用与源码配套的 CN 6.0.2 资源；更新服务端程序并重启后出现入口。沿用客户端已有的聊天功能，无需修改 APK。

1. 点击“新增表情”，填写名称并选择类型。编号自动分配，范围为 980001–989999；最多保存200个表情。分类默认跟随类型，也可选择游戏已有的交流、战术、指示等分类。
2. 纯文字填写文字内容；图片类型上传 PNG／JPEG，建议256×256透明PNG。每张最多4MB，边长64–4096像素，总像素不超过800万；导出时等比例缩放至256×256并补透明边。名称最多40字，内容／说明最多100字；使用中文标点，不能包含英文逗号、双引号、标签或换行。
3. 图片加声音同时上传图片和 MP3／WAV。声音源文件最多8MB、最长30秒，浏览器自动转换为PCM WAV；可试听并调整0–100%音量。全部图片和转换后的声音合计最多16MB。音量仅调整导出副本，保存的声音原件保留；游戏仍遵循玩家的表情声音设置。
4. 点击“保存草稿”。图片、声音和设计保存在SQLite，刷新或重启保留。导入／导出设计JSON可备份或转移；导入时保留当前草稿中未包含在文件内的已发布表情。并发保存检查版本，旧页面不能覆盖新版本。已发布表情不能移除，可保留编号修改名称、文字、图片、声音或类型。
5. 点击“生成资源更新包”。生成客户端 `stamp.csv`、独立表情贴图、服务端表情master、后台缩略图、版本／CRC／SHA-256清单。带声音的设计还生成 `resources/cpk/CueSheet_Card_981.cpk` 和 `versions.json`；声音编号使用902000001–902009999，与自制卡牌声音分开。旧资源缺少语音版本文件时，补建仅登记新声音包的版本表，其他语音沿用默认版本1。
6. 正常停服并备份资源与数据库。核对ZIP中 `configuration.json` 的 `base_sha256` 与运行资源一致；空值表示新文件，目标路径应尚不存在。将ZIP内 `resource-set/` 按原路径合并覆盖，保留数据库和部署配置，再重启服务。使用CDN时同步变更的资源、语音和清单。不同更新包应依次基于已应用资源生成。
7. 客户端重新进入并下载更新后，从“礼物发放”、表情商店、任务或兑换奖励选择新表情。保存草稿、生成ZIP均不会自动发布或发放。玩家领取后在游戏聊天编成中装配，仍使用原来的12个槽位。

资源导出使用纯Go，不依赖Unity Editor、Python或外部音频编码器。会检查当前清单基准；不支持的资源布局或不一致的资源拒绝导出。运行时master新增可选 `kind` 字段，用于自制表情的奖励名称和图片预览，资源包须与新版程序一起使用。

验证覆盖草稿持久化、版本冲突、上传校验、编号占用与发布保护、三种类型资源导出、再次修改和声音版本递增；浏览器验证覆盖预览、上传、保存与桌面／手机布局。独立Unity资源读取校验验证贴图像素、路径、对象引用与清单哈希。Android设备上的聊天编成、实际声音和多人接收仍需游戏内验收。
