# 自制卡牌

后台侧栏的“自制卡牌”可以制作独立的新卡：分别上传 PNG/JPEG 卡面小图、普通卡面和完整立绘，编辑名字、冠名、职业、属性、COST、稀有度、卡牌详情，以及初始／满级／满忠诚度的四维数值；从现有卡牌中选择技能效果，调整数值、添加、删除或排序。

页面已嵌入服务端程序。首次使用需按 [构建说明](BUILD.md) 更新程序并重启，资源使用与源码版本配套的完整 `resource-set/`。不需要在 Unity 中制作二维卡面。

本次卡牌导出验证所用的旧运行包含有变身资源历史字段 `imported_costume_rewards`，而当前源码读取 `costume_rewards`。该旧包尚未完成与新程序的整包运行验收，部署前需要更新配套资源；卡牌更新包只处理卡牌及其图片、技能，不迁移其他历史资源格式。

## 制作与发布

1. 点击“从现有卡复制”，选择资源完整的普通卡。可一次选择多张；各张新卡自动分配独立 ID 和技能 ID。
2. 编辑基本信息和四维。职业可以选通用／佣兵／富豪／盗贼／歌姬，第一属性从火／冰／风／光／暗中选择；第二属性可选另一种不同属性，留空为单属性，支持全部10种双属性组合。COST 为 1–10。双属性同步到普通／觉醒技能及服务端合成属性；直接攻击与效果来源分支属性一致时随卡牌转换，原本指定其他属性的攻击继续保留。双属性卡的附魔、属性防御等指定单一属性的效果保留来源属性，不自动增加第二项效果；单属性卡仍沿用原来的转换规则。双属性攻击沿用原版结算，不会额外增加攻击次数。设计JSON继续使用 `attribute` 字段，例如 `FIRE_ICE`；保存时按火、冰、风、光、暗顺序规范化。旧单属性草稿继续兼容。修改后须保存并重新生成、应用资源更新包，让客户端下载更新，无需修改APK。
3. 分别上传卡面小图、普通卡面和完整立绘，或沿用模板。小图建议256×256；普通卡面建议5∶7构图（如1000×1400），用于竖向卡框；完整立绘建议1024×1024透明PNG，用于放大图和出牌特写。普通卡面默认“铺满卡框”，等比例裁切超出边缘，也可选择“完整显示”保留整张图并补透明边。未单独上传普通卡面时从完整立绘生成；只上传普通卡面时保留模板完整立绘。未上传小图时优先从完整立绘生成，其次从普通卡面生成；只上传小图时保留模板普通及放大立绘。游戏贴图最终尺寸沿用模板，无需手工压扁图片。每张PNG/JPEG最多4MB、宽高各64–4096像素且总像素不超过800万；全部草稿中的三种图片和转换后的自制语音合计最多16MB。旧设计的 `artwork` 字段继续保存完整立绘，`icon_artwork` 保存小图，`card_artwork` 保存独立普通卡面；`card_artwork_mode` 为 `cover` 或 `contain`，省略时默认铺满。
4. 在相应效果组点击“从现有卡添加效果”，选择来源卡，再选该卡的一项效果。页面与选择窗口均显示中文效果名称、用途、中文目标和参数含义；每项数值显示单位及当前百分比换算，修改后立即更新。当前资源使用的54种玩家效果均有说明，包括攻击、回复、支援、妨害、持续伤害和特殊效果。注意暴击率使用千分比（150=15%），吸血比例使用百分比（50=50%），反弹使用万分比（770=7.7%）；固定能力提升中的倍率字段也不是能力类型。公式中的等级指卡牌等级；实际结果还可能受Chain、属性、防御、抗性及模板分支影响。保留字段会明确提示，未识别的新效果不会猜测单位。效果按当前顺序执行；每个原有条件分支至少保留一项效果。结合来源卡说明调整开放的数值参数，并更新技能名称和说明；数值占位符例如 `{1}` 应按原格式保留。
5. 点击“保存草稿”。设计和卡面保存到 SQLite，重启保留；“导出设计 JSON”可以备份或转移设计。最多保存 200 张卡，每组至少保留一项、最多5项效果，每个技能ID最多5个条件分支。新增文本请使用中文逗号，不能换行。需要改变演出时，在“出牌演出”选择特写来源，在各效果组选择动作来源；两项分别保存，可分别恢复模板。
6. 点击“生成资源更新包”，下载 ZIP。导出会校验服务端卡牌数据及战斗效果定义，并同步客户端表、卡面、资源版本、CRC 和清单哈希。导出不会自动更新运行中的游戏，也不会自动发卡。
   旧的分属性演出补丁可能只修改 `skill_role_player.csv` 第4列的 `_cp_support_*`、`_cp_disruption_*`、`_cp_defense_*`、`_cp_healing_*` 引用及换行，没有更新清单。导出仅在去掉这些已知属性后缀并恢复 CRLF 后，文件大小和 SHA-256 均与清单原表完全一致时接受这一基准；更新包同步清单与字节汇总，`configuration.json` 仍记录当前服务器文件的实际哈希。自制卡的这些动作别名还须在原动作支持的各角色资源目录中完整登记；资源不齐时，自制卡回退至已有原动作，避免只闪卡面却跳过技能动作和特效。原动作也未登记时拒绝导出。其他列、技能数值、范围、行序或未知演出变更不适用此兼容规则。无需把服务器技能表替换为原版，也不会在导出时改写运行目录。
7. 停服并备份运行目录的资源和数据库，核对 ZIP 中 `configuration.json` 的 `base_sha256` 与当前原文件一致。将 ZIP 内 `resource-set/` 的内容按原路径合并覆盖到运行目录的 `resource-set/`，然后重启。保留现有数据库和部署配置；多个更新包应依次基于已应用的资源生成，不能从同一旧版本分别导出后混合覆盖。
8. 使用 CDN 时，将变更的资源与清单同步到 CDN。客户端重新进入并下载资源更新后，在“礼物发放”、卡池或兑换所中使用新卡 ID 提供给玩家。

**需要打包进 `resource-set/`。** 后台保存的是设计，客户端必须同时取得新卡表、技能表和图片资源。页面会生成所需的更新包，无需手工编辑 `container.dat` 或仅把 PNG 丢进资源文件夹；这些新增卡牌使用已有客户端功能，无需修改 APK。

已有资源包含放大卡面服务 `cn-image-root` 时，更新包也会添加对应 PNG 和图片清单。旧资源没有此入口时，仍会生成模板对应的客户端卡面贴图；独立放大图片服务需要完整配套资源。

普通立绘／卡牌图标与点击后的放大图使用不同资源。早期导出包曾保留模板的图片目录，出现放大图有图、普通立绘或图标为空的问题。更新服务端后，用原来的卡牌设计重新生成更新包并按上述流程应用，即可修正同一张卡的图片引用，无需删除卡牌、换 ID 或清除玩家存档。使用 CDN 时也须同步更新后的贴图、清单和版本文件，再重新进入游戏下载资源。

原版卡牌的普通卡面（`chr10`）和完整立绘（`chr60`／`chr51`）是独立构图的资源，图标（`chr20`）和特写（`chr50`）也分别加载。普通卡面的正方形贴图会显示为400×560的竖向区域，特写贴图显示为613×490。导出器按显示比例补偿，并按普通卡面的构图模式铺满裁切或完整留边；完整立绘和小图分别生成。上一版仅修正比例并居中留边，会让方形原图在竖向卡框中出现上下空带。更新服务端后，选择“铺满卡框”或单独上传适合竖框的普通卡面，用原设计重新生成并应用资源更新包即可；只更换程序不会改变客户端已有贴图。原图本身的透明区和截断边缘不会被自动补画，需要换用合适构图的原图。

上传卡面后，导出器会按新卡编号同步生成普通卡面和图标的目录、贴图名称与包内加载路径。旧模板清单未记录 `container_path` 时，会从资源目录、名称和扩展名补全。导出前必须确认普通卡面、图标及相应包内贴图和加载路径都存在；缺失或引用错误会在后台报错，不再生成只有放大立绘可用的更新包。

## 模板继承与验收

稀有度（星级）可独立选择1–8星，不受模板星级限制；默认沿用模板，也可随时恢复。设计JSON的 `rarity_rank` 为可选整数1–8，缺省或null沿用模板；旧草稿无需修改。保存后重新生成并应用资源更新包，客户端与服务端同步使用所选星级。明确选择星级时，等级上限、名声上限、忠诚度上限及经验表同步采用该星级的普通卡规则（五星50级／90名声，六星60级／100名声，七星80级／100名声；八星沿用原版特殊的1级规则）。同星级六星模板已有的一／二次突破保留65／70级，跨星级不继承突破阶段。省略星级仍沿用模板。稀有度PLUS、技能条件及自定义属性独立保留，名声培养可独立设置；修改星级不会自动加入进化链；出牌语音默认沿用模板，可另选现有卡牌录音或上传自制语音。可组合现有的战斗效果，但不能在页面编写新效果代码或新增触发条件。效果类型沿用效果来源卡，目标范围可调整；可编辑的“参数 1、2……”按项目原始参数规则开放，含义随效果变化，例如倍率、成长、基础数值或持续回合，不能跨效果套用同一解释。

「卡牌详情」可编辑游戏内角色介绍、画师、声优、性别、三围、身高、体重和惯用手。角色介绍最多2000字，其他项最多100字；可留空清除或逐项恢复模板，不能包含英文逗号、双引号或换行。声优项只修改显示署名，录音在“出牌语音”中单独设置。设计JSON中的 `details` 是可选对象，字段为 `description`、`illustrator`、`voice_actor`、`gender`、`measurements`、`height`、`weight`、`hand`；缺省或null继承模板，空字符串清除。旧草稿继续继承模板。保存后重新生成并应用资源更新包，让客户端下载更新后生效，无需修改APK。

每个技能分支可分别编辑技能名称、技能副名和技能介绍。「技能副名」对应游戏中技能名称下方的小字，最多60字，可留空清除；不能包含英文逗号、双引号或换行。保存草稿后重新生成并应用资源更新包，客户端更新资源后生效。

每项效果单独显示「目标范围」，明确区分己方全体、己方单体、自身和敌方目标。沿用技能选择目标的效果会展开当前关联技能的范围；多个关联分支的目标不同则分别列出。添加效果窗口也按加入后的当前效果组显示目标范围，排除自身的效果会标明。

「技能目标」决定出牌时选择的对象，可选自身、己方单体／全体、敌方单体／全体；攻击技能提供敌方单体／全体。普通技能与觉醒技能可分别修改，同一技能的条件分支同步使用相同目标。「效果目标」可沿用技能目标，也可指定独立范围；直接攻击效果提供沿用技能目标、敌方单体／全体。例如用露萨莉制作全队双攻卡时，把普通和觉醒技能目标都选为己方全体，两项攻击能力提升的效果目标选为沿用技能目标。修改后须同步技能介绍，再保存并生成、应用资源包。

改变技能目标时，相关已选择的技能动作会恢复模板，可重新选择与新目标范围匹配的动作来源。技能数值和实际结算按新目标执行，演出仍使用已有客户端脚本；请在Android检查单体与全体动画及命中特效。

在各效果组点击「添加特殊效果」，选择「本回合单体全体化」。它是一项独立技能效果，可与现有效果组合，也可移除模板的其他效果，仅保留这一项。普通技能与觉醒技能对应的效果组须分别配置，共用效果组的条件分支一起生效；每组仍最多5项。仅保留此效果时，不会产生模板原有的攻击、回复或增益，也不显示原来的威力数值；卡面、语音和动作仍可沿用或选择现有来源。

在效果行的“全体化生效对象”选择“自身有用”“己方一人有用”或“全队有用”。新增效果默认仅自身；选择己方一人会自动把关联技能目标设为己方单体，出牌时选择要获得全体化能力的角色（须使用允许己方单体目标的回复、支援等模板）。这里指定的是谁后续出牌可以单体转全体，不是增益或回复最终能覆盖谁。普通技能和觉醒技能的效果组分别设置。

本卡完整结算后，所选角色本回合后续实际打出的手牌中，己方单体及自身目标效果变为己方全体，敌方单体变为敌方全体；独立指定的单体及自身效果也会转换，原全体范围保持不变。各目标按原伤害、回复或支援公式分别结算，不平分数值；属性筛选和排除自身等限制仍生效。例如“己方1人提升暴击率＋自身提升回复量”在获得能力的角色出牌时，两项都作用于己方全体。自身回复、自伤及自身吸血回复也会扩展到己方全体；吸血按每位存活目标各自的HP上限与回复限制结算。效果公式中的“参照自身能力”仍读取原施放者，不更换能力来源。此效果只作用于后续手牌，不改变Boss招式、Sphere技能或祝福追加技能；不叠加扩大范围，下一回合及下一波战斗清除。实际发动顺序沿用技能优先级，先选牌不保证先发动，请选择合适模板并同步填写技能说明。

设计JSON使用 `roles` 中的 `TURN_SINGLE_TO_ALL` 效果，来源为 `{ "card_id": 0, "index": 0 }`，目标由生效对象选项生成，参数1固定为`1`以标记可选范围版本，其他参数保持为空。旧版`SELF`且参数为空的效果仍按全队生效，编辑范围后写为新版格式。服务端技能表保存独立效果；客户端导出为零数值的原生占位效果，保留行序与演出，无需新增客户端效果类型。必须使用配套新版服务端并重新生成、应用卡牌资源包；Android动画及命中特效仍须实测。

旧草稿的 `turn_single_to_all` 开关仍可读取；编辑器会为各效果组添加全队范围的独立效果并提示保存。若某组已有5项，会保留旧效果并提示先腾出一个位置，不会删除原有效果。重新导出时也会更新旧 `_local/control/server/cn602-battle-master/custom_card_effects.json`，清除已改为独立效果的卡牌标记。

「出牌语音」可分别选择攻击／妨害／特殊技能和回复／支援／防御技能的语音来源卡，并选择该卡的攻击类或支援类语音，两类可交叉使用。选择来源复用已有的客户端录音，没有可用语音的卡牌会提示更换来源；也可上传自制录音，详见下方说明。可分别恢复模板。语音选择、出牌台词和卡牌详情的声优署名互不影响，不自动改写字幕。设计JSON中的 `attack_voice_source`、`support_voice_source` 为可选对象，格式为 `{ "card_id": 10000010, "kind": "attack" }`，`kind` 可选 `attack`／`support`；缺省或null沿用模板。保存、生成并应用资源更新包后生效，无需修改APK。

「出牌台词」对应战斗演出时画面最下方的字幕，与技能副名分别编辑。攻击／妨害／特殊技能使用一类台词，回复／支援／防御技能使用另一类；每类最多100字，可留空清除或恢复模板台词。不能包含英文逗号、双引号或换行。这里只修改字幕，语音由「出牌语音」配置；未选择来源或上传音频时使用模板录音。设计JSON中的 `attack_dialogue`、`support_dialogue` 为可选字符串，缺省或null沿用模板，空字符串清除。旧草稿继续沿用模板；保存后重新生成并应用资源更新包，无需修改APK。

技能介绍框下方显示所用占位符对应的分支、效果、展示值含义、计算公式与当前原始参数，并提供含义预览、跳转到对应效果、点击插入可用占位符。修改参数、介绍或效果顺序时对应关系会更新。占位符读取客户端计算后的展示值，不直接对应原始参数序号：同一技能根的分支每个占50个位置，每个效果占10个位置，客户端最多展示前5个分支、各分支前5个效果。例如第一分支第二个效果的第1个展示值为 `{11}`，第二分支第一个效果的第1个展示值为 `{51}`。普通技能和职业技能各自从0开始编号。

直接攻击的 `{1}` 通常是固定伤害及等级成长部分，`{2}` 是参照能力的百分比，`{3}` 是攻击次数，`{4}` 是暴击率百分比；编号随效果位置变化。介绍中的百分号须自行填写。未知、未定义或已被移除的展示位置会明确提示待确认，不提供猜测数值。预览用于核对含义，具体显示数值由客户端按卡牌等级、整数转换规则计算；它不表示实战最终伤害。祝福的展示位置7–9来自独立的介绍基础值和成长字段，修改这些字段不会修改呼出技能的战斗效果。

出牌特写与攻击／技能动作可以分别选择现有卡牌作为来源，未选择时沿用模板。特写配置复制卡牌表的特写样式，仍展示自制卡自己的卡面；动作按效果组选择，复制来源的2D技能脚本、3D动作播放表、命中特效、蓄力及电影演出引用。动作来源须与当前组具有相同的技能类型和目标范围，并同时提供2D脚本及3D动作。3D特写样式与动作独立；2D整段技能演出随动作来源切换。界面不能上传新的骨骼动画或编写演出脚本，独立新动作需要制作配套客户端资源。

技能条件仍来自模板，出牌语音可沿用模板、选择现有来源卡或上传自制录音；上传新卡面不会新增语音或特效，改变属性也不会自动改写演出颜色。新卡拥有独立同卡身份，不自动加入原卡进化链。多个技能分支共用同一效果组时，编辑动作或效果会影响这些分支。旧草稿没有演出来源字段时继续使用模板，重新导出后新选择才进入客户端。

早期导出可能在上移、删除或替换效果后丢失模板演出：客户端只读取每组首行的演出字段，而后续效果行可能没有这些字段。修复后的导出保留所选动作来源的整组演出，未另选动作时保留模板演出，并限制每组最多5项效果及每个技能ID最多5个条件分支，避免客户端读取固定数组时越界。遇到出牌无动画或已出牌仍留在出牌区域时，更新服务端后用原设计重新生成并应用资源包；已有超过5项的效果组须先减少数量。同步CDN后让客户端重新下载资源，再检查单人和多人出牌。无需更换卡牌ID或清除存档。

若服务器曾装过只改技能表的分属性演出补丁，导出的自制卡可能引用没有配套资源的动作，例如 `pl_buff_buff_b_cp_support_wind`。客户端此时能显示特写和台词，却无法播放角色动作，战斗中的状态更新也可能缺少正常演出。更新后的导出器会将资源不完整的已知别名恢复为已有原动作，例如 `pl_buff_buff_b`；不会修改卡牌数值、技能目标、持续回合或出牌顺序。需要重新生成并应用资源包，只替换程序不会修复客户端已有的技能表。加攻、加防在该卡结算时立即生效，后续同回合攻击使用新数值；选牌时的显示数值不能代替实际伤害结算。

打包会按实际交付的 `version.dat` 更新动作资源清单中的版本哈希，版本表不会把自身登记为 Unity 资源。更换同一卡牌 ID 的模板或重新生成卡面时，同一个逻辑图片名称只保留当前资源引用，清除该卡旧模板的重复引用。旧的合成包可能因版本哈希不一致、资源数量不一致或逻辑图片重复而在启动时被拒绝；应使用配套修正版清单及版本表重新应用，不能跳过启动校验。资源合成后的验收应包含实际服务器启动及游戏、后台健康检查。

已应用的卡牌可以继续编辑并重新导出，不能从草稿删除，以免玩家库存失去卡牌定义。更新四维时资源包会推进成长配置版本，现有卡牌重新按新数值计算，并保留等级、名声、忠诚度与拥有状态。

发布后在 Android 中检查卡面、图鉴、编组、等级和忠诚度数值、技能说明、普通／职业技能及条件分支，并验证单人和多人战斗的效果顺序。服务器与资源结构检查通过不代表移动客户端动态验收已经完成。

## 自制出牌语音

在“出牌语音”中，可分别设置攻击／妨害／特殊技能和回复／支援／防御技能语音。“选择语音来源”可复用原卡的任一类别；“上传自制语音”接受单／双声道 MP3 或 WAV，原文件最多8MB、时长最多30秒。页面会转换为22050Hz单声道PCM WAV，并提供试听；保存草稿或导出设计JSON时保留音频。上传和来源选择会互相替换，“恢复模板语音”清除当前类别的自定义设置。语音、文字台词和详情声优署名分别编辑。

自制语音可独立设置0–100%的音量，试听和导出到游戏的音量同步；觉得过响可先设为50%。设计字段 `attack_voice_volume` / `support_voice_volume` 为可选整数，省略时保持100%，兼容旧设计。原始WAV保留在草稿中，降低音量只影响导出副本，重复导出不会越变越小；恢复模板或选择现有语音时清除对应音量设置。调整后须保存并重新生成、应用资源更新包。

设计字段 `attack_voice_source` / `support_voice_source` 为 `{card_id,kind}`，`kind` 为 `attack` 或 `support`。自制音频字段 `attack_voice_audio` / `support_voice_audio` 为16位PCM WAV的Base64；同一类别不能同时设置来源和音频。旧草稿省略这些字段时沿用模板。

生成更新包时，服务器将上传音频编码为ADX并生成配套ACB／AWB，统一放入 `resources/cpk/CueSheet_Card_980.cpk`，同步语音版本表和资源清单。服务器不需要安装FFmpeg或另行执行编码程序。应用资源后须同步CPK到CDN，让客户端重新下载语音；修改录音会推进语音包版本。该资源文件由本编辑器保留使用，不能覆盖同名外部资源。部署报告不重复携带WAV数据，完整设计应另行导出JSON备份。

游戏用ADX须匹配CN602客户端的全局Atom解密配置；未加密的ADX在后台WAV试听及独立解码时正常，但进入游戏会被错误解密，导致整句严重失真。导出器会按客户端音频密钥处理各声道的ADX块，保留原始WAV及后台试听。此前已导出的语音需要使用修复后的程序重新生成并应用资源包，无须重新上传录音，也无须改变卡牌ID。只替换服务程序不能修复客户端已经缓存的旧CPK。

## 允许名声强化

“允许名声强化（名声培养）”只控制名声培养。关闭后仍能合成同卡叠名声，并保留已有名声、名声上限和培养消耗。开启后使用模板的培养消耗；模板没有设置时，每点名声使用原版常见的20名声素材。客户端的培养／分解类型是单选，启用培养会替代模板的分解资格；关闭培养不会移除模板原有的分解资格。已付费开始的培养可以完成或取消，关闭后不能新开培养。

设计字段 `allow_fame_training` 为布尔值；省略或null沿用模板，false关闭，true开启。更新包同时修改客户端卡表的培养类型／消耗和服务器运行主表；同卡身份及名声最大值不改。开启或关闭后都需要重新生成并应用资源更新包才能在游戏中生效。

## 开发验证

在 `server/` 中运行 `go test ./...` 和 `go vet ./...`。完整资源导出测试默认跳过；设置 `CN602_CUSTOM_CARD_RESOURCE_SET` 为完整资源目录后运行 `go test ./internal/admin -run Custom -count=1` 和 `go test ./internal/criaudio -count=1`。语音验证包含CPK目录、ACB元数据、AWB及ADX波形；仍需在Android中实际出牌试听。测试读取原资源，导出的文件仅写入临时目录，不修改源资源、数据库或运行中的服务。

## 自制卡进化链路

在自制卡编辑页的“进化链路”选择进化后的自制卡及材料配方，可设置例如 5 星 UR → 6 星 MR 的普通进化。进化前后是两张独立 ID 的卡，可分别配置卡面、四维和技能；它们共享同卡系列，不能作为同系列的两张卡同时编入卡组。普通进化前后职业须一致，目标星级须提高，素材与金币沿用所选现有普通进化路线，且配方的前后星级必须与自制卡一致。

卡面星级沿用原版显示：5 星可进化到 6 星时显示五颗亮星和第六颗空星，进化后六颗亮星。导出包含进化终点的空记录，让客户端正确计算整条链的最高星级；没有进化路线的卡只显示当前星级。旧更新包若缺少空星提示，使用新版程序重新生成、应用资源更新包并让客户端下载即可，无需重建卡牌或更换 ID。

还没有进化后形态时，先选择材料配方，再点击“按配方新建进化形态”：系统复制配方原卡的进化后模板，分配新 ID，继承当前自制卡的名字、冠名、职业和属性，自动连接进化路线。随后编辑新形态的卡面、数值和技能；等级上限、成长等沿用新形态模板。也可以先从现有卡复制制作目标，再在原形态选择它。

保存草稿后生成资源更新包，按包内说明应用资源并重启；使用 CDN 时同步更新。客户端重新下载资源后，在游戏的进化入口将满级原形态进化为目标形态，消耗配方所需金币与素材；名声、忠诚度、锁定和卡牌实例 ID 按原进化逻辑保留，等级是否保留沿用配方。后台“进化链”也可查看并关闭这条路线。清除或更换目标须重新生成、应用更新包；旧路线会同步从客户端和服务端移除。不能移除已经发布的卡牌草稿；不能将多条普通进化链汇合到同一目标。尚未配置进化的旧设计文件继续按独立卡牌导出。

## 已发布卡牌的旧设计兼容

已发布自制卡按其卡牌 ID 识别归属；生成记录中的模板 ID 仅记录上次使用的模板。旧草稿的模板与该记录不同，也可以继续修改并保存同一 ID，更新时保留玩家已有的卡牌实例。

导入旧设计或只包含部分卡牌的设计时，文件中出现的 ID 使用导入内容更新；文件中未包含的已发布卡牌自动从当前草稿保留，不会从编辑列表、资源或玩家库存消失。仍然不能移除已发布卡牌；原版卡和缺少生成归属记录的其他占用 ID 也不能被覆盖。导出会保留未参与此次更新的已发布卡牌生成记录。
