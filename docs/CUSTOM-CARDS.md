# 自制卡牌

后台侧栏的“自制卡牌”可以制作独立的新卡：上传 PNG/JPEG 卡面，编辑名字、冠名、职业、属性、COST，以及初始／满级／满忠诚度的四维数值；从现有卡牌中选择技能效果，调整数值、添加、删除或排序。

页面已嵌入服务端程序。首次使用需按 [构建说明](BUILD.md) 更新程序并重启，资源使用与源码版本配套的完整 `resource-set/`。不需要在 Unity 中制作二维卡面。

本次卡牌导出验证所用的旧运行包含有变身资源历史字段 `imported_costume_rewards`，而当前源码读取 `costume_rewards`。该旧包尚未完成与新程序的整包运行验收，部署前需要更新配套资源；卡牌更新包只处理卡牌及其图片、技能，不迁移其他历史资源格式。

## 制作与发布

1. 点击“从现有卡复制”，选择资源完整的普通卡。可一次选择多张；各张新卡自动分配独立 ID 和技能 ID。
2. 编辑基本信息和四维。职业可以选通用／佣兵／富豪／盗贼／歌姬，属性可选五种单属性，COST 为 1–10。
3. 上传卡面，或沿用模板卡面。每张 PNG/JPEG 最多 4MB、尺寸 64–4096 像素且总像素不超过 800 万；全部草稿中的图片合计最多 16MB。图片保持比例并补透明边，自动生成客户端贴图和后台缩略图。
4. 在相应效果组点击“从现有卡添加效果”，选择来源卡，再选该卡的一项效果。效果按当前顺序执行；每组至少保留一项、最多5项效果，每个技能ID最多5个条件分支。结合来源卡说明调整开放的数值参数，并更新技能名称和说明；数值占位符例如 `{1}` 应按原格式保留，新增文本请使用中文逗号，不能换行。
5. 点击“保存草稿”。设计和卡面保存到 SQLite，重启保留；“导出设计 JSON”可以备份或转移设计。最多保存 200 张卡。
6. 点击“生成资源更新包”，下载 ZIP。导出会校验服务端卡牌数据及战斗效果定义，并同步客户端表、卡面、资源版本、CRC 和清单哈希。导出不会自动更新运行中的游戏，也不会自动发卡。
7. 停服并备份运行目录的资源和数据库，核对 ZIP 中 `configuration.json` 的 `base_sha256` 与当前原文件一致。将 ZIP 内 `resource-set/` 的内容按原路径合并覆盖到运行目录的 `resource-set/`，然后重启。保留现有数据库和部署配置；多个更新包应依次基于已应用的资源生成，不能从同一旧版本分别导出后混合覆盖。
8. 使用 CDN 时，将变更的资源与清单同步到 CDN。客户端重新进入并下载资源更新后，在“礼物发放”、卡池或兑换所中使用新卡 ID 提供给玩家。

**需要打包进 `resource-set/`。** 后台保存的是设计，客户端必须同时取得新卡表、技能表和图片资源。页面会生成所需的更新包，无需手工编辑 `container.dat` 或仅把 PNG 丢进资源文件夹；这些新增卡牌使用已有客户端功能，无需修改 APK。

已有资源包含放大卡面服务 `cn-image-root` 时，更新包也会添加对应 PNG 和图片清单。旧资源没有此入口时，仍会生成模板对应的客户端卡面贴图；独立放大图片服务需要完整配套资源。

普通立绘／卡牌图标与点击后的放大图使用不同资源。早期导出包曾保留模板的图片目录，出现放大图有图、普通立绘或图标为空的问题。更新服务端后，用原来的卡牌设计重新生成更新包并按上述流程应用，即可修正同一张卡的图片引用，无需删除卡牌、换 ID 或清除玩家存档。使用 CDN 时也须同步更新后的贴图、清单和版本文件，再重新进入游戏下载资源。

## 模板继承与验收

第一版沿用模板的稀有度、等级上限、成长方式、名声规则、语音、条件分支和演出。可组合现有的战斗效果，但不能在页面编写新效果代码或新增触发条件。效果的目标、类型沿用来源卡，整组演出资源沿用模板；可编辑的“参数 1、2……”按项目原始参数规则开放，含义随效果变化，例如倍率、成长、基础数值或持续回合，不能跨效果套用同一解释。

技能条件和演出仍来自模板，上传新卡面不会新增语音或特效，改变属性也不会改写演出颜色。新卡拥有独立同卡身份，不自动加入原卡进化链。多个技能分支共用同一效果组时，编辑该组会影响这些分支。

早期导出可能在上移、删除或替换效果后丢失模板演出：客户端只读取每组首行的演出字段，而后续效果行可能没有这些字段。修复后的导出始终保留模板演出，并限制每组最多5项效果及每个技能ID最多5个条件分支，避免客户端读取固定数组时越界。遇到出牌无动画或已出牌仍留在出牌区域时，更新服务端后用原设计重新生成并应用资源包；已有超过5项的效果组须先减少数量。同步CDN后让客户端重新下载资源，再检查单人和多人出牌。无需更换卡牌ID或清除存档。

已应用的卡牌可以继续编辑并重新导出，不能从草稿删除，以免玩家库存失去卡牌定义。更新四维时资源包会推进成长配置版本，现有卡牌重新按新数值计算，并保留等级、名声、忠诚度与拥有状态。

发布后在 Android 中检查卡面、图鉴、编组、等级和忠诚度数值、技能说明、普通／职业技能及条件分支，并验证单人和多人战斗的效果顺序。服务器与资源结构检查通过不代表移动客户端动态验收已经完成。

## 开发验证

在 `server/` 中运行 `go test ./...` 和 `go vet ./...`。完整资源导出测试默认跳过；设置 `CN602_CUSTOM_CARD_RESOURCE_SET` 为完整资源目录后运行 `go test ./internal/admin -run Custom -count=1`。测试读取原资源，导出的文件仅写入临时目录，不修改源资源、数据库或运行中的服务。
