# 自制卡牌

后台侧栏的“自制卡牌”可以制作独立的新卡：分别上传 PNG/JPEG 卡面小图、普通卡面和完整立绘，编辑名字、冠名、职业、属性、COST，以及初始／满级／满忠诚度的四维数值；从现有卡牌中选择技能效果，调整数值、添加、删除或排序。

页面已嵌入服务端程序。首次使用需按 [构建说明](BUILD.md) 更新程序并重启，资源使用与源码版本配套的完整 `resource-set/`。不需要在 Unity 中制作二维卡面。

本次卡牌导出验证所用的旧运行包含有变身资源历史字段 `imported_costume_rewards`，而当前源码读取 `costume_rewards`。该旧包尚未完成与新程序的整包运行验收，部署前需要更新配套资源；卡牌更新包只处理卡牌及其图片、技能，不迁移其他历史资源格式。

## 制作与发布

1. 点击“从现有卡复制”，选择资源完整的普通卡。可一次选择多张；各张新卡自动分配独立 ID 和技能 ID。
2. 编辑基本信息和四维。职业可以选通用／佣兵／富豪／盗贼／歌姬，属性可选五种单属性，COST 为 1–10。
3. 分别上传卡面小图、普通卡面和完整立绘，或沿用模板。小图建议256×256；普通卡面建议5∶7构图（如1000×1400），用于竖向卡框；完整立绘建议1024×1024透明PNG，用于放大图和出牌特写。普通卡面默认“铺满卡框”，等比例裁切超出边缘，也可选择“完整显示”保留整张图并补透明边。未单独上传普通卡面时从完整立绘生成；只上传普通卡面时保留模板完整立绘。未上传小图时优先从完整立绘生成，其次从普通卡面生成；只上传小图时保留模板普通及放大立绘。游戏贴图最终尺寸沿用模板，无需手工压扁图片。每张PNG/JPEG最多4MB、宽高各64–4096像素且总像素不超过800万；全部草稿中的三种图片合计最多16MB。旧设计的 `artwork` 字段继续保存完整立绘，`icon_artwork` 保存小图，`card_artwork` 保存独立普通卡面；`card_artwork_mode` 为 `cover` 或 `contain`，省略时默认铺满。
4. 在相应效果组点击“从现有卡添加效果”，选择来源卡，再选该卡的一项效果。页面与选择窗口均显示中文效果名称、用途、中文目标和参数含义；每项数值显示单位及当前百分比换算，修改后立即更新。当前资源使用的54种玩家效果均有说明，包括攻击、回复、支援、妨害、持续伤害和特殊效果。注意暴击率使用千分比（150=15%），吸血比例使用百分比（50=50%），反弹使用万分比（770=7.7%）；固定能力提升中的倍率字段也不是能力类型。公式中的等级指卡牌等级；实际结果还可能受Chain、属性、防御、抗性及模板分支影响。保留字段会明确提示，未识别的新效果不会猜测单位。效果按当前顺序执行；每个原有条件分支至少保留一项效果。结合来源卡说明调整开放的数值参数，并更新技能名称和说明；数值占位符例如 `{1}` 应按原格式保留。
5. 点击“保存草稿”。设计和卡面保存到 SQLite，重启保留；“导出设计 JSON”可以备份或转移设计。最多保存 200 张卡，每组至少保留一项、最多5项效果，每个技能ID最多5个条件分支。新增文本请使用中文逗号，不能换行。需要改变演出时，在“出牌演出”选择特写来源，在各效果组选择动作来源；两项分别保存，可分别恢复模板。
6. 点击“生成资源更新包”，下载 ZIP。导出会校验服务端卡牌数据及战斗效果定义，并同步客户端表、卡面、资源版本、CRC 和清单哈希。导出不会自动更新运行中的游戏，也不会自动发卡。
7. 停服并备份运行目录的资源和数据库，核对 ZIP 中 `configuration.json` 的 `base_sha256` 与当前原文件一致。将 ZIP 内 `resource-set/` 的内容按原路径合并覆盖到运行目录的 `resource-set/`，然后重启。保留现有数据库和部署配置；多个更新包应依次基于已应用的资源生成，不能从同一旧版本分别导出后混合覆盖。
8. 使用 CDN 时，将变更的资源与清单同步到 CDN。客户端重新进入并下载资源更新后，在“礼物发放”、卡池或兑换所中使用新卡 ID 提供给玩家。

**需要打包进 `resource-set/`。** 后台保存的是设计，客户端必须同时取得新卡表、技能表和图片资源。页面会生成所需的更新包，无需手工编辑 `container.dat` 或仅把 PNG 丢进资源文件夹；这些新增卡牌使用已有客户端功能，无需修改 APK。

已有资源包含放大卡面服务 `cn-image-root` 时，更新包也会添加对应 PNG 和图片清单。旧资源没有此入口时，仍会生成模板对应的客户端卡面贴图；独立放大图片服务需要完整配套资源。

普通立绘／卡牌图标与点击后的放大图使用不同资源。早期导出包曾保留模板的图片目录，出现放大图有图、普通立绘或图标为空的问题。更新服务端后，用原来的卡牌设计重新生成更新包并按上述流程应用，即可修正同一张卡的图片引用，无需删除卡牌、换 ID 或清除玩家存档。使用 CDN 时也须同步更新后的贴图、清单和版本文件，再重新进入游戏下载资源。

原版卡牌的普通卡面（`chr10`）和完整立绘（`chr60`／`chr51`）是独立构图的资源，图标（`chr20`）和特写（`chr50`）也分别加载。普通卡面的正方形贴图会显示为400×560的竖向区域，特写贴图显示为613×490。导出器按显示比例补偿，并按普通卡面的构图模式铺满裁切或完整留边；完整立绘和小图分别生成。上一版仅修正比例并居中留边，会让方形原图在竖向卡框中出现上下空带。更新服务端后，选择“铺满卡框”或单独上传适合竖框的普通卡面，用原设计重新生成并应用资源更新包即可；只更换程序不会改变客户端已有贴图。原图本身的透明区和截断边缘不会被自动补画，需要换用合适构图的原图。

上传卡面后，导出器会按新卡编号同步生成普通卡面和图标的目录、贴图名称与包内加载路径。旧模板清单未记录 `container_path` 时，会从资源目录、名称和扩展名补全。导出前必须确认普通卡面、图标及相应包内贴图和加载路径都存在；缺失或引用错误会在后台报错，不再生成只有放大立绘可用的更新包。

## 模板继承与验收

沿用模板的稀有度、等级上限、成长方式、名声规则、语音和条件分支。可组合现有的战斗效果，但不能在页面编写新效果代码或新增触发条件。效果类型沿用效果来源卡，目标范围可调整；可编辑的“参数 1、2……”按项目原始参数规则开放，含义随效果变化，例如倍率、成长、基础数值或持续回合，不能跨效果套用同一解释。

每个技能分支可分别编辑技能名称、技能副名和技能介绍。「技能副名」对应游戏中技能名称下方的小字，最多60字，可留空清除；不能包含英文逗号、双引号或换行。保存草稿后重新生成并应用资源更新包，客户端更新资源后生效。

每项效果单独显示「目标范围」，明确区分己方全体、己方单体、自身和敌方目标。沿用技能选择目标的效果会展开当前关联技能的范围；多个关联分支的目标不同则分别列出。添加效果窗口也按加入后的当前效果组显示目标范围，排除自身的效果会标明。

「技能目标」决定出牌时选择的对象，可选自身、己方单体／全体、敌方单体／全体；攻击技能提供敌方单体／全体。普通技能与觉醒技能可分别修改，同一技能的条件分支同步使用相同目标。「效果目标」可沿用技能目标，也可指定独立范围；直接攻击效果提供沿用技能目标、敌方单体／全体。例如用露萨莉制作全队双攻卡时，把普通和觉醒技能目标都选为己方全体，两项攻击能力提升的效果目标选为沿用技能目标。修改后须同步技能介绍，再保存并生成、应用资源包。

改变技能目标时，相关已选择的技能动作会恢复模板，可重新选择与新目标范围匹配的动作来源。技能数值和实际结算按新目标执行，演出仍使用已有客户端脚本；请在Android检查单体与全体动画及命中特效。

「出牌台词」对应战斗演出时画面最下方的字幕，与技能副名分别编辑。攻击／妨害／特殊技能使用一类台词，回复／支援／防御技能使用另一类；每类最多100字，可留空清除或恢复模板台词。不能包含英文逗号、双引号或换行。这里只修改字幕，语音仍使用模板录音。设计JSON中的 `attack_dialogue`、`support_dialogue` 为可选字符串，缺省或null沿用模板，空字符串清除。旧草稿继续沿用模板；保存后重新生成并应用资源更新包，无需修改APK。

技能介绍框下方显示所用占位符对应的分支、效果、展示值含义、计算公式与当前原始参数，并提供含义预览、跳转到对应效果、点击插入可用占位符。修改参数、介绍或效果顺序时对应关系会更新。占位符读取客户端计算后的展示值，不直接对应原始参数序号：同一技能根的分支每个占50个位置，每个效果占10个位置，客户端最多展示前5个分支、各分支前5个效果。例如第一分支第二个效果的第1个展示值为 `{11}`，第二分支第一个效果的第1个展示值为 `{51}`。普通技能和职业技能各自从0开始编号。

直接攻击的 `{1}` 通常是固定伤害及等级成长部分，`{2}` 是参照能力的百分比，`{3}` 是攻击次数，`{4}` 是暴击率百分比；编号随效果位置变化。介绍中的百分号须自行填写。未知、未定义或已被移除的展示位置会明确提示待确认，不提供猜测数值。预览用于核对含义，具体显示数值由客户端按卡牌等级、整数转换规则计算；它不表示实战最终伤害。祝福的展示位置7–9来自独立的介绍基础值和成长字段，修改这些字段不会修改呼出技能的战斗效果。

出牌特写与攻击／技能动作可以分别选择现有卡牌作为来源，未选择时沿用模板。特写配置复制卡牌表的特写样式，仍展示自制卡自己的卡面；动作按效果组选择，复制来源的2D技能脚本、3D动作播放表、命中特效、蓄力及电影演出引用。动作来源须与当前组具有相同的技能类型和目标范围，并同时提供2D脚本及3D动作。3D特写样式与动作独立；2D整段技能演出随动作来源切换。界面不能上传新的骨骼动画或编写演出脚本，独立新动作需要制作配套客户端资源。

技能条件和语音仍来自模板，上传新卡面不会新增语音或特效，改变属性也不会自动改写演出颜色。新卡拥有独立同卡身份，不自动加入原卡进化链。多个技能分支共用同一效果组时，编辑动作或效果会影响这些分支。旧草稿没有演出来源字段时继续使用模板，重新导出后新选择才进入客户端。

早期导出可能在上移、删除或替换效果后丢失模板演出：客户端只读取每组首行的演出字段，而后续效果行可能没有这些字段。修复后的导出保留所选动作来源的整组演出，未另选动作时保留模板演出，并限制每组最多5项效果及每个技能ID最多5个条件分支，避免客户端读取固定数组时越界。遇到出牌无动画或已出牌仍留在出牌区域时，更新服务端后用原设计重新生成并应用资源包；已有超过5项的效果组须先减少数量。同步CDN后让客户端重新下载资源，再检查单人和多人出牌。无需更换卡牌ID或清除存档。

已应用的卡牌可以继续编辑并重新导出，不能从草稿删除，以免玩家库存失去卡牌定义。更新四维时资源包会推进成长配置版本，现有卡牌重新按新数值计算，并保留等级、名声、忠诚度与拥有状态。

发布后在 Android 中检查卡面、图鉴、编组、等级和忠诚度数值、技能说明、普通／职业技能及条件分支，并验证单人和多人战斗的效果顺序。服务器与资源结构检查通过不代表移动客户端动态验收已经完成。

## 开发验证

在 `server/` 中运行 `go test ./...` 和 `go vet ./...`。完整资源导出测试默认跳过；设置 `CN602_CUSTOM_CARD_RESOURCE_SET` 为完整资源目录后运行 `go test ./internal/admin -run Custom -count=1`。测试读取原资源，导出的文件仅写入临时目录，不修改源资源、数据库或运行中的服务。
