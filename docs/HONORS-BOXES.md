# 称号与礼盒后台配置

运营后台新增“称号与礼盒”页签。资源中已有的自定义称号（ID ≥ 26000000）、礼盒 9999 以及后来生成的自定义礼盒作为初始配置。官方称号和普通道具保留原定义。

1. 点击“新增称号”，填写名称并选择 A／B／C／特殊称号佩戴槽位。ID 自动分配，默认不授予玩家。
2. 点击“新增礼盒”，设置名称、说明、最大持有量，并复用一个已有礼盒图标。ID 和开箱功能值自动分配。
3. 从奖励目录选择卡牌、素材、道具、皮肤或称号，也可以把当前草稿中的新称号直接加入奖池。填写数量和正整数权重，页面实时显示概率。每箱随机抽取一项；皮肤和称号每次只能发放一个。
4. 保存配置。草稿存入 SQLite，刷新或重启后台保留，不会自动发奖或改变玩家库存。导入／导出 JSON 可备份配置。并发保存检查配置版本，旧页面不能覆盖新版本。
5. 点击“生成资源更新包”。后台使用纯 Go 生成客户端 `container.dat`、道具和称号 master、图标及资源版本／CRC／SHA-256 清单。不依赖 Python、Unity Editor，也不修改 APK。
6. 停服并备份，将下载包里的 `resource-set` 按路径合并覆盖到生成它的运行资源集，重启服务，让客户端重新下载资源。保存草稿和下载 ZIP 本身不会发布运行资源。
7. 应用资源后通过原有后台发放礼盒或配置掉落。手机上的实际显示、开箱和佩戴需要设备验收。

更新包的 `configuration.json` 提供原资源 SHA-256，适用于生成时的完整资源集。目标已有其他修改时先比较合并；不要用旧补丁覆盖新资源。当前支持 CN 6.0.2 的 UnityFS 6、SerializedFile 14–17、未加扰的 `main_c/container.dat`，使用无压缩或 LZ4 的输入。遇到不支持的布局、校验不一致或缺失表时返回错误，不生成半成品更新包。

客户端表只替换目标记录，保持其他原始 CSV 行、Unity 对象、资源路径和对象 ID。输出依旧采用 UnityFS／LZ4，资源清单自动合并新增图标并更新后台目录计数。
